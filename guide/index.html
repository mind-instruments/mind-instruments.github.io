管理者 · Q1

如何啟動雲端版本並完成管理者基本設定？

驗證方式：業務資料及帳號 ID 保留；最高管理者已經本人設定新密碼並成功登入。三種身分使用隔離雲端驗收。

  1. 直接開啟 CNMM 公開網站。電腦與手機只需瀏覽器及網路，不需安裝 Node.js、Supabase CLI 或啟動 Start-AFM.cmd。
  2. 最高管理者請使用已交付的登入信箱，以及本人在密碼設定入口自行設定的新密碼登入。既有一般帳號則使用自己的登入資料。資料庫已有帳號，所以不會出現首次建立最高管理者的入口，也不需要在 Supabase Auth 新增同名帳號。
  3. 若出現強制換密碼畫面，依提示輸入目前密碼與不同的新密碼；未完成前不能進入管理或切換測試角色。
  4. 按「切換管理模式」，依序處理 Q2 實驗室、Q3 成員與管理者、Q4 儀器認證、Q5–Q6 儀器與規則、Q7–Q8 耗材。既有設定不需重建。
  5. 另以隔離測試帳號依 Q17、Q10、Q19、Q22 演練預約、核准、簽到簽退與探針簽署；勿在正式資料建立假使用紀錄。

完成時應看到：登入後顯示原身分及資料；頁面風格不變，新增資料存到 Supabase。

卡住時先檢查：原本首次啟用流程只適用全新本機資料。此次已遷移的雲端禁止公開自封最高管理者。忘記密碼可使用登入頁的復原入口；若寄件服務不可用，請由已授權維運者處理，勿刪除資料或建立另一套帳號庫。

管理者 · Q2

如何新增實驗室，讓新用戶選擇單位並申請登入？

驗證方式：歷輪畫面實測

  1. 使用主系統管理者登入，按「切換管理模式」→ 左側「帳號與權限」。
  2. 按「新增實驗室」，輸入明確且不重複的實驗室名稱，按「確認送出」。
  3. 讓新用戶開啟同一套網站的登入頁，按「申請新帳號」。若註冊頁早已開著，先重新整理再選單位。
  4. 新用戶填姓名、電子郵件、密碼及確認密碼，在「所屬實驗室」選剛建立的實驗室，再按「申請帳號 →」。
  5. 回到管理者帳號，按「帳號與權限」，找到該成員並依下一題設定。

完成時應看到：註冊選單可選到新實驗室；新用戶可登入，但會顯示「帳號等待實驗室管理者核准」。

卡住時先檢查：新增實驗室不會自動建立登入帳號，也不會自動核准成員。若選不到單位，先核對是否進入同一個網站。

管理者 · Q3

如何指定實驗室管理者並核准一般成員？

驗證方式：歷輪畫面實測：主系統將成員 D 設為實驗室管理者；重新登入可切管理模式，帳號清單僅限實驗室 A，不能編輯同級代表。

  1. 先請要擔任代表的人用自己的信箱申請帳號，選正確實驗室。
  2. 主系統管理者進入「帳號與權限」→ 該人的「設定權限」。
  3. 確認「所屬單位」；代表的「層級」設為「實驗室管理者」，一般成員維持「一般使用者」。
  4. 將「帳號狀態」設為「已核准」。依需求勾選「可申請預約」與「可簽署已個別授權的耗材」，按「確認送出」。
  5. 實驗室管理者重新整理或重新登入後可切換管理模式；往後可管理直屬一般成員。再依下一題配置儀器認證。

完成時應看到：帳號列顯示正確單位、角色與已核准狀態。

卡住時先檢查：一般成員與實驗室管理者不能自行升為最高管理者。實驗室管理者不能調整自己或其他管理者的資格；請主系統管理者處理。

如何查看全站成員：主系統管理者開「管理模式 → 帳號與權限」，可依實驗室、角色、姓名或信箱篩選，再依實驗室、權限層級、姓名或預約頻率排序。預約頻率顯示所選近 30／90／365 天內、以開始時間計算的已核准場次；不含待審、取消與退回。實驗室管理者只看自己的單位。

管理者 · Q4

如何設定每個人能使用哪些儀器？

驗證方式：歷輪畫面實測

  1. 切換管理模式 →「儀器認證」。可用姓名／信箱搜尋，主系統管理者也可篩選實驗室。
  2. 找到人員所在列、目標儀器所在欄，選擇「未認證／代工／一般／進階」。
  3. 逐格確認後按「儲存認證」，直到顯示已儲存。只改下拉選單尚未保存。
  4. 請使用者重新整理「儀器預約」，核對資格標示與可選時段。主系統管理者若自己要預約，也要設定自己的儀器資格。

完成時應看到：一般資格可在一般開放時段自行操作；代工資格只走代工；進階資格走自行操作並依規則開放進階時段。

卡住時先檢查：未認證不能預約。帳號已核准、可申請預約、個人儀器認證、儀器開放與時段規則都須符合。多人同時改認證出現衝突時，重載後重新核對，勿盲目覆寫。

管理者 · Q5

如何加入新儀器、設定使用模式與故障選項？

驗證方式：歷輪畫面實測：新增第二台儀器、自訂使用模式、個別規則與保存

  1. 主系統管理者切換管理模式 →「儀器預約」→「＋ 新增儀器」。
  2. 填名稱、位置及狀態，指定儀器管理員，確認使用模式與簽退狀態；新儀器先用清楚的獨立名稱。
  3. 按「確認送出」。在上方「儀器」選單選回該儀器，再按「儀器設定」檢查。
  4. 要修改選項，按「編輯儀器」或「編輯選單」。異常選項可要求說明，會阻擋預約的狀態需明確設定。
  5. 到「儀器認證」授予使用者資格；到該儀器的「耗材」建立專屬針表。

完成時應看到：各儀器有自己的預約、設定與耗材。歷史簽退保留當時的選項名稱。

卡住時先檢查：只有被授權的儀器管理員／主系統管理者看得到儀器設定。新儀器不會自動承襲每個人的認證。

管理者 · Q6

如何限制週末、晚間與延長預約的批准者？

驗證方式：歷輪畫面實測：一般資格的週末及晚間顯示資格限制，點週末不能選；平日可選。改為進階並重新整理後，週末與晚間可選，實際送出週末預約。後臺直接請求也拒絕一般資格週末預約。規則及資格切換由隔離後臺設定，管理畫面保存沿用歷輪證據。

  1. 切換管理模式 →「預約規則」，開啟修改規則。
  2. 設定一般時段開始與結束、單次上限、週末及一般時段外的開放對象。
  3. 設定「延長批准權限」為實驗室管理者或主系統管理者，確認送出。
  4. 若特定儀器要使用個別規則，到「儀器預約」選儀器 →「儀器設定」→「編輯儀器」，啟用個別規則後保存。
  5. 用一般／進階資格分別檢查週末與晚間時段；以使用者實際看到的可選格位為準。

完成時應看到：不符規則的格位顯示資格限制；延長申請交由規則指定角色處理。

卡住時先檢查：實驗室規則不能超出主系統允許的範圍；進階資格也不能繞過停機、衝突等限制。

如何確認規則真的生效：以一般成員登入 → 選儀器 → 查看週末／晚間格。若限制為進階，格子應寫「資格限制」，按下不會選取；管理者修改資格後按「重新整理」，再檢查格子與確認清單。管理者身分的豁免不能用來代表一般成員測試。

管理者 · Q7

如何加入新探針，建立數量正確的針盒表格？

驗證方式：v6.0 遷移輪雲端 API 建立 2×3、6 支針盒，含名稱、日期、供應商；畫面核對欄位。

  1. 切換管理模式 →「儀器預約」，先在「儀器」選單確認儀器，再按「耗材」→「＋ 建立針盒」。
  2. 填「針盒名稱」與「耗材型號」；編號前綴只用英文字母、數字、底線或連字號。例如名稱「OPUS 2026-11 第一盒」、前綴「OPUS2611A」。
  3. 填「實收數量」與「訂購數量」。只收到 6 支就填實收 6，不要把尚未到貨的數量當可領庫存。
  4. 先輸入數量讓系統自動排格，再視需要手動改列數／欄數；確認「格位容量」足以容納訂購數量。上限為 26 列 × 20 欄、520 支。
  5. 填單價、供應商、批號、採購日期、到貨日期、儲位；補貨交期與安全庫存依需要填寫。主系統管理者要再確認「所屬單位」。
  6. 選針盒照片：JPEG／PNG／WebP、3 MB 內。按「確認送出」，回到針盒摘要核對名稱、數量、格位、單位與照片。此時仍是草稿。

完成時應看到：6 支可自動排成 A1–A6；收到與訂購分開記錄，草稿尚不能讓使用者簽領。

卡住時先檢查：供應商、批號、採購日期、到貨日期和照片在發佈前都必須齊全。選「中心庫存」代表待購用途，不等於直接授權某實驗室簽領。

管理者 · Q8

如何補傳照片、設定領用權限並發佈針盒？

驗證方式：v6.0 遷移輪雲端照片實際上傳、授權、發佈與跨實驗室照片拒絕通過；畫面顯示照片並成功編輯儲位。

  1. 在「耗材」的「針盒」選單選既有草稿。若照片缺失，按「編輯資料與照片」，選有效照片，按「確認送出」。
  2. 核對畫面已出現照片。若顯示資料已保存但照片尚未完成，留在同一針盒補傳；不要再按「建立針盒」。
  3. 按「批次領用權限」，勾選可領用的同實驗室成員，按「確認送出」。成員帳號仍須有「可簽署已個別授權的耗材」。
  4. 按「預覽並發佈」，核對針盒名稱、實收數量、列欄及照片，再按「確認送出」。
  5. 用一般成員帳號登入，選同一儀器與針盒，確認能看見 A1 等格位並顯示可簽署。

完成時應看到：摘要顯示「已發佈」，有授權的使用者才能簽領；未發佈的草稿不出現在一般成員清單。

卡住時先檢查：沒有照片或採購資料時，發佈會被拒絕。歷輪修正了照片失敗後重送會新增第二張針表的問題。若建立操作本身結果不明，先依斷線復原提示檢查，不要另建一盒。

如何從 CSV 或 ICS 匯入預約，避免時區與重複資料錯誤？

驗證方式：歷輪實際操作檔案選擇器：有效 CSV 後換超大檔，重現舊內容殘留並修正；複驗清空舊內容及顯示欄內錯誤，再換有效 CSV 可預覽送審。ICS 自動辨識、UTC 轉台北時段及送審成功。帶毫秒 ISO 時間曾被錯誤拒絕，修正後通過；檔案讀取失敗、競速、關閉與清除分支另有自動回歸。

Q73 · 如何在還原或 Google 授權到期後恢復同步？

管理者／維運

  1. 先確認預約與耗材資料已按 Q51、Q52 完整還原。
  2. 保留 CNMM 專用加密金鑰；既有資料備份含加密的個人日曆授權，但不含雲端環境金鑰。
  3. 寄件者授權與進行中的 Google 登入狀態不在目前業務資料備份內；還原後需要重新授權寄件帳號。
  4. 個人日曆若顯示需重新授權，由各使用者在帳戶頁重新連結；交接職務不會轉交個人的 Google 授權。
  5. Google 已正式發布。由測試切換正式後，在帳戶頁分別重新授權日曆與寄件帳號，更新舊的測試授權。正式授權仍可能因使用者撤銷、密碼或 Google 政策變更失效；顯示需重新授權時，使用原帳戶重新連結。

外部服務權限、金鑰和資料備份必須分開核對。本輪已完成真實授權與寄送 API 驗收，Google 正式發布已完成；長期運作穩定性及 Google 應用程式驗證仍未完成。
